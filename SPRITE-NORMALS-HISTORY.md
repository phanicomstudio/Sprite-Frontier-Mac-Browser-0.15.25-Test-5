# Sprite normals — implementation checkpoint

The lighting workbench loads artwork, generates approximate rounded silhouette normals, paints height, imports height, imports a matching normal PNG, previews lighting/normal/height and exports normal/height PNGs. Working artwork is capped at 512 pixels per side; imported normals must match those working dimensions. Normal RGB uses +Y upward. Artwork owns transparency. Height edits regenerate normals and replace an imported normal draft.

Shared sprite-lighting preparation validates settings and dimensions and produces isolated lit pixels. Source fixtures verify light direction, alpha preservation, unchanged source pixels and invalid-input rejection. A real Chrome workbench test imported a flat normal PNG, checked exact preview pixels and rejected mismatched dimensions without a page error.

Remaining required work: persistent per-sprite bindings, Apply/Remove controls, runtime prepared-image caching, complete generation/import/apply/remove/save/reload scenario and visual/performance verification. The workbench export is not yet an applied game lighting feature.

2026-10-08 progress: workbench now loads a registered sprite profile, Apply saves its generated/imported normal PNG and light on the current map through the undoable mutation path, and Remove deletes that binding. Runtime prepares a full-sheet lit image asynchronously, retains up to 64 MB with an 8-million-pixel sheet cap, and reuses it without per-frame pixel work. Browser acceptance verified Apply/Remove, real playtest preparation, stable preparation count over later frames and zero retained bytes after removal. The supplied armed sheet is 1200 × 4800; the processing dimension bound was expanded to 8192 to support it. Full alpha/frame-crop visual QA, saved project reload, undo/redo, peak transient memory and hitch measurements remain required. Prior export-only checkpoint is superseded.

Persistence acceptance: live Chrome test removed a binding, restored it with editor Undo, exported all maps, imported that project and verified the retained binding while original maps remained intact. Full cached source suite rerun after integration. Preparation now processes at most 32 rows per scheduled task and checks revision cancellation between tasks, preventing one full-sheet blocking pixel loop. The lit image becomes visible only when all batches finish. Peak memory and actual frame timing are not yet measured.

Measured headless Chrome/Pixi WebGL run: armed sheet 1200 × 4800 (5,760,000 pixels), 23,040,000 retained prepared-image bytes, 600 eight-row tasks, about 3.97 seconds total preparation and 41.5 ms maximum measured batch. The original sprite remains visible while preparation runs. CPU-backed read-heavy canvases and scalar normal calculations reduce allocation/readback overhead, but a worst-case batch still exceeds a 16.7 ms frame budget. Do not claim hitch-free preparation or native-platform performance. NORMAL-PERFORMANCE.json retains raw diagnostics and frame callback timestamps; callback timestamps are not a substitute for wall-clock task profiling. Screenshot inspection showed intact character alpha and frame positioning, but multi-direction crop comparison remains pending. Future improvement: off-thread preparation or prebuilt lit variants, validated against memory and image fidelity.

Worker update supersedes the CPU-only timing above: portable Blob worker now performs reads and shading off-thread using the same serialized pure lighting functions. Measured worker processing of the 1200 × 4800 sheet was ~172.7 ms (150 worker batches); its 27.6 ms worst batch runs in the worker, not in the gameplay task. Bitmap creation/adoption and GPU upload still require separate main-thread profiling. Unsupported worker/OffscreenCanvas environments retain the eight-row fallback. Revision cancellation aborts the worker and releases its bitmap/object URL; tests verify exact worker/reference pixels including transparent pixels, aborted preparation, Apply/Remove, undo and project import/export. Retained prepared-image storage remains 23.04 MB. macOS verification is pending.

## Validation and fallback checkpoint

Normal extension namespaces retain bounded finite JSON objects (maximum depth12, 2048 visited values, 4096 serialized characters). Invalid values reject before map adoption rather than silently disappearing on export. Browser tests pass normal Apply/Remove, prepared-image reuse and cleanup with worker preparation disabled, exercising the asynchronous CPU path. The CPU path is functional but slower; see NORMAL-PERFORMANCE.json and the asset guide.
